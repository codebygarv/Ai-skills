## Purpose

Generate a set of technical interview questions for a given role/skill area, paired with a concrete evaluation rubric — so interviews are structured and comparable across candidates, not improvised each time.

## When to Use

- Preparing to interview a candidate for a specific role or skill area.
- An interview loop needs consistent questions across interviewers.
- Existing interview questions feel stale, too generic, or don't actually test what the role needs.

## What to Analyze / Do

1. **Clarify what's actually being assessed** — a specific skill area (e.g. "React component design," "SQL query writing," "system design for a backend role"), seniority level, and time budget.
2. **Generate questions that discriminate** — questions where a strong candidate's answer clearly differs from a weak one, not questions with a single memorizable correct answer that only tests recall.
3. **Mix question types appropriately for the time budget** — e.g. one deeper problem plus a couple of follow-up probes, rather than many shallow questions if time is short.
4. **Write a rubric per question** — what a strong, adequate, and weak answer each look like, so different interviewers score consistently.
5. **Include likely follow-up probes** for each question — what to ask if the candidate's first answer is too shallow, to get more signal.

## Output Format

- For each question: the question itself, what it's assessing, the rubric (strong/adequate/weak signals), and 1-2 follow-up probes.
- Ordered roughly by difficulty or logical flow (easier/broader first, if applicable).
- A note on total suggested time budget across the set.

## Avoid

- Trivia-style questions that just test memorization of a specific fact/API rather than actual understanding or problem-solving.
- Questions with a single "gotcha" correct answer with no room for a candidate to demonstrate reasoning.
- Generating questions detached from the stated seniority level (e.g. asking senior-level system design questions for an entry-level role).
