# 📊 Status Update Writer

Turn scratch notes into an update people will actually read.

## What it does

Converts rough dev notes into a structured status update (Done / In Progress / Blocked / Next), grouping related micro-tasks into outcome-level lines and making blockers explicit and actionable.

## When to use it

- Writing a daily/weekly status update from rough notes.
- Turning a stream-of-consciousness task list into something shareable.
- Standardizing update format across a team.

## Best for

- Daily/weekly team standup-style updates
- Cross-functional or leadership-facing status reports
- Making blockers visible and actionable instead of buried

## Example usage

> "Turn these notes into a status update: fixed the login bug, still working on the payments refactor, need design's input on the checkout flow before I can finish the UI"

## Expected output

A Done / In Progress / Blocked / Next update (or the team's existing format), concise and outcome-oriented, with blockers stating what's needed to resolve them.

## Limitations

- Tone/audience matching depends on being told (or it being clear) who the update is for — ask if it's ambiguous whether this is internal-technical or stakeholder-facing.
- Won't soften a real risk or slipping timeline into vague language — if the notes indicate something's at risk, the update says so.
