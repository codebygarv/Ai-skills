# 🗺️ Project Planner

Turn an idea into a plan people can actually start executing.

## What it does

Breaks an idea or feature into phases, concrete tasks, and dependencies, with a critical path and a risks/unknowns section — sequenced so genuine unknowns surface early instead of being discovered mid-build.

## When to use it

- An idea hasn't been broken into actionable phases/tasks yet.
- Kicking off a nontrivial feature and want a shared plan before work starts.
- Coordinating work across people/teams where task ordering matters.

## Best for

- Turning a feature idea into an execution plan
- Surfacing dependencies and the critical path before work starts
- Sequencing risky/uncertain work early to de-risk the rest

## Example usage

> "Plan out building a real-time notifications system for our app."

## Expected output

A goal statement with scope notes, phases with tasks and dependencies, a critical-path callout, and a risks/unknowns section explaining why each risk matters and how it's sequenced to surface early.

## Limitations

- Doesn't produce time estimates/dates by default — sequencing and dependencies are the core output; ask explicitly if estimates are needed, and provide team/velocity context for them to be meaningful.
- Plan quality depends on a clear goal — pair with [Requirements Extractor](../../reasoning/requirements-extractor/) first if the goal itself is still vague.
